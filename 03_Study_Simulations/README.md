# Monkey study-design simulations

This folder contains the current three-step reanalysis of reduced exploratory
monkey PK study designs. The analysis asks how well sparse studies recover PK
endpoints when both uncertain mAb/target parameters and between-monkey
physiology are represented explicitly.

The primary analysis isolates study-design performance by comparing each sparse
study with its own replicate-matched dense population truth. A separate
secondary analysis compares the same sparse estimates with fixed nominal
typical-subject endpoints. These two comparisons answer different questions and
must remain separate.

## Current truth models

| Molecule | Truth model | Important qualification |
|---|---|---|
| Golimumab | Nominal, uncalibrated Anti-TNFA monkey model | Uses the configured central model inputs |
| Nivolumab | Calibrated Anti-PD1 monkey model | Structurally identical to the a priori Anti-PD1 model, but the FcRn `Kd` center is 0.39 micromol/L |

Uncalibrated Nivolumab simulations are not part of this exercise.

## Variability hierarchy

Two coefficient-of-variation scenarios are evaluated: 30% and 60%. Positive
uncertain inputs are sampled from lognormal distributions parameterized so that
their arithmetic means equal the applicable truth-model centers.

### Replicate-level parameter uncertainty

One five-parameter draw is one Monte Carlo replicate. The following values are
drawn once per molecule, variability scenario, and replicate, then held fixed
across every monkey and dose in that replicate:

1. FcRn binding affinity (`Kd`);
2. target binding affinity (`Kd`);
3. target dissociation rate (`koff`);
4. complex internalization rate (`kint`); and
5. target degradation rate (`kdeg`).

There are 100 replicates for every molecule and variability scenario.

### Between-monkey population variability

Every molecule, CV, replicate, and dose uses the same base body-weight
population of 50 virtual monkeys. Only these model inputs vary between monkeys:

- body weight, generated by the PK-Sim monkey population workflow using the
  configured 3--7 kg range; and
- target reference concentration, sampled at the scenario-specific 30% or 60%
  CV and re-centered to retain the exact configured arithmetic mean.

Target reference concentration is represented only at the population level. It
is generated once for each molecule and CV, reused across all replicates and
doses in that cell, and is not also drawn at the replicate level. This avoids
duplicate nested variability for the same biological quantity.

Endogenous IgG is fixed between monkeys in this analysis. FcRn abundance or
function is also fixed between monkeys. Uno, Utoh, and Iwasaki reported that
none of the nonsynonymous `FCGRT` or `B2M` variants they assessed in cynomolgus
and rhesus macaques changed residues known to be important for FcRn function,
and concluded that substantial inter-animal FcRn variability was not expected
in the cynomolgus macaques analyzed ([Uno et al., 2014](https://doi.org/10.2133/dmpk.DMPK-14-NT-033)).

## Study-design configuration

| Setting | Current value |
|---|---|
| Variability scenarios | 30% and 60% CV |
| Parameter replicates | 100 per molecule and CV |
| Virtual monkeys | 50 |
| Replicates per simulation checkpoint | 10 |
| Simulated doses | 0.1, 1, 3, 10, and 30 mg/kg |
| Two-dose design | 1 and 10 mg/kg |
| Three-dose design | 0.1, 1, and 10 mg/kg |
| Five-dose design | 0.1, 1, 3, 10, and 30 mg/kg |
| Monkeys per dose group | 2, 3, or 6 |
| Dense grid | Every 0.25 h through 8 h, then hourly through 28 days |
| Sparse grid | 0.25, 1, 2, 4, and 8 h; days 1, 2, 6, 10, 14, 21, and 28 |

The full population simulation contains 100,000 profiles before sparse
sampling:

```text
2 molecules x 2 CV scenarios x 100 replicates x 50 monkeys x 5 doses
```

## Run order

Run the scripts in order from the repository root.

### Step 1: Prepare inputs

```powershell
quarto render ".\03_Study_Simulations\Scripts\Step1_Prepare_Study_Design_Inputs.qmd"
```

Step 1 validates the truth models, creates the parameter draws and populations,
and constructs the dose, time-grid, and checkpoint manifests. It does not run
concentration-time simulations. Review its rendered HTML before starting Step
2.

To keep the output folder focused, diagnostic tables and plots remain embedded
in the HTML. Only four downstream artifacts are saved separately under
`SimsOutputs/Step1_Inputs/`:

- `Objects/study_design_step1_inputs.rds`;
- `Tables/study_design_parameter_draws.csv`;
- `Tables/study_design_base_monkey_population.csv`; and
- `Tables/study_design_target_population.csv`.

### Step 2: Run simulations

```powershell
quarto render ".\03_Study_Simulations\Scripts\Step2_Run_Study_Design_Simulations.qmd"
```

Step 2 locks the two truth simulations, creates one dense nominal
typical-subject profile for every molecule and dose, and runs the population
profiles in independent batches. The full design has 200 checkpoints:

```text
2 molecules x 2 CV scenarios x 5 doses x 10 replicate batches
```

Each checkpoint contains 10 parameter replicates crossed with 50 monkeys, or
500 population profiles at one molecule, CV, and dose. A checkpoint is saved
immediately after it passes validation. Rerendering Step 2 reuses every valid
checkpoint and runs only missing or incompatible batches.

Set the following only when all simulation checkpoints should be recomputed
deliberately:

```powershell
$env:STUDY_DESIGN_FORCE_RERUN = "true"
```

The main Step 2 locations are:

- `SimsOutputs/Step2_Simulations/Checkpoints/` for population checkpoints;
- `SimsOutputs/Step2_Simulations/Objects/study_design_nominal_typical_dense_profiles.rds`
  for the secondary nominal reference; and
- `SimsOutputs/Step2_Simulations/Objects/study_design_step2_run_index.rds`
  for the validated checkpoint inventory consumed by Step 3.

Step 2 records the checksum of the Step 1 input object. Existing checkpoints
are accepted only if their input checksum, truth model, CV, dose, replicate
membership, and dense grid match the current run.

### Step 3: Post-process results

```powershell
quarto render ".\03_Study_Simulations\Scripts\Step3_Postprocess_Study_Design_Results.qmd"
```

Step 3 streams the simulation checkpoints into resumable endpoint checkpoints,
samples the candidate sparse studies, calculates fold errors, and writes tables
and figures under `SimsOutputs/Step3_Results/`.

For a given molecule, CV, replicate, dose, and group size, monkeys are sampled
without replacement within the dose group. Sampling is independent between
dose groups, so the same monkey may appear at different doses. The same selected
monkeys are used for AUC, Cmax, and clearance. Candidate designs that contain
the same dose and group size share that dose group's sampled monkeys.

If Step 3 is interrupted, rerender it to reuse valid endpoint checkpoints. Set
the following only for a deliberate complete endpoint recalculation:

```powershell
$env:STUDY_DESIGN_FORCE_POSTPROCESS = "true"
```

## Endpoint rules

The analysis calculates:

- AUC0-28d by the linear-up/log-down trapezoidal method;
- Cmax as the maximum sampled concentration; and
- terminal clearance from `AUCinf = AUClast + Clast/lambda_z`, where the
  terminal phase is the best post-Cmax suffix containing at least three points
  by adjusted R-squared.

When no time-zero value is present, the first sampled concentration is carried
back to time zero, matching the prior workflow.

## Primary and secondary fold errors

### Primary: replicate-matched study-design error

The dense truth for each dose is the arithmetic mean of the evaluable individual
dense endpoints for the same molecule, CV, and parameter replicate. This is
normally all 50 monkeys. A profile that has no concentration-time output after
the Step 2 batch and single-profile retries is excluded only from its exact
matched dose cell. Other doses from that monkey remain eligible, and sparse
sampling for the affected cell uses the same reduced eligible pool. Step 3 saves
the explicit exclusions in `study_design_excluded_failed_profiles.csv` and
reports the resulting dense-truth denominators in its HTML and QC outputs.

```text
primary fold error = sparse study mean / replicate-matched dense population truth
```

This comparison controls for the replicate's uncertain parameter draw and is
the primary measure of how well the sparse design recovers its own underlying
population truth.

Key outputs include:

- `study_design_replicate_matched_dense_truth.csv`;
- `study_design_replicate_matched_fold_error.csv`;
- `study_design_fold_error_summary.csv`; and
- `study_design_replicate_matched_fold_error.png`.

### Secondary: total deviation from the nominal prediction

The secondary denominator is the fixed dense typical-subject endpoint generated
from central truth-model inputs for each molecule and dose.

```text
secondary fold error = sparse study mean / nominal typical-subject endpoint
```

This quantity combines sparse-design error with the difference between the
replicate-specific population truth and the nominal prediction:

```text
sparse / nominal = (sparse / matched truth) x (matched truth / nominal)
```

It can show a broader, more visually realistic total deviation, but it must not
be interpreted as design error alone.

Key outputs include:

- `study_design_nominal_typical_reference_endpoints.csv`;
- `study_design_nominal_typical_fold_error.csv`;
- `study_design_nominal_typical_fold_error_summary.csv`; and
- `study_design_nominal_typical_fold_error.png`.

The figures mark 0.5- and 2-fold boundaries. This interval is a prespecified
tutorial criterion, not a universal study-design acceptance rule.

## Reproducibility notes

- Fixed seeds are recorded for population generation, parameter draws, target
  variability, and sparse animal selection.
- Step 1 is the source of truth for analysis settings. After changing it,
  rerender Steps 1, 2, and 3 in order.
- Do not combine checkpoints or results from different Step 1 input checksums.
- Persistent Step 2 profile failures are retained in the audit trail. Step 3
  excludes them dose-specifically rather than discarding the full parameter
  replicate or silently changing the denominator.
- Do not rename output files or directories without updating all downstream
  paths and validation rules together.
- Review the HTML reports, failed-profile table, checkpoint inventories,
  artifact manifests, and session information before interpreting results.
